# Testcase: original 240-km MPAS-BMatrix NMC calibration

This directory holds the complete **scientific YAML contract** from the
validated x1.10242 experiment. The MPAS-BMatrix package is generic and selects
no case implicitly. This testcase is selected only by passing its
`jaci.yaml` to `--config`.

## Structure

- `jaci.yaml`: JACI runtime, mesh geometry/partition (128 ranks, 55 levels),
  original static data, explicitly selected MPAS namelist/streams and support
  files. Includes the shared site policy at `../../configs/jaci.yaml`.
- `bmatrix.yaml`: scientific-contract aggregator.
- `stages/`: **original** YAML fragments for controls, BFLOW, VBAL,
  UNBALANCE (optional historical A/B), HDIAG, NICAS, SO and DIRAC.
  Their scientific numbers, variables, and formulas were copied unchanged.
- `run.sh`: checks the selected configuration or consumes MPASWF products.

## Reproduce the NMC tutorial

After MPASWF has produced its manifest:

```bash
CASE=testcase/tutorial-240km/jaci.yaml
MANIFEST=/p/projetos/monan_das/$USER/work/mpaswf/products/mpas-forecast-manifest.tsv
mpas-bmatrix check-config --config "$CASE"
mpas-bmatrix check-manifest --config "$CASE" --manifest "$MANIFEST"
mpas-bmatrix build --config "$CASE" --manifest "$MANIFEST" --from-stage bflow --to-stage dirac
```

Or run from any working directory:

```bash
bash testcase/tutorial-240km/run.sh check
bash testcase/tutorial-240km/run.sh dry-run "$MANIFEST"
bash testcase/tutorial-240km/run.sh build "$MANIFEST"
```

`check-config --json` prints the full machine-readable configuration;
without it the output prioritizes failures and their corrections.

The testcase uses the original external JACI geometry, invariant, MPAS
atmosphere files, MONAN-JEDI install, runtime stack, and a matching MPASWF
manifest. They must be present on the user's system; this repository does
not contain the original NetCDF inputs or reference outputs.

## Use as a template for other meshes and periods

Copy the entire testcase directory, then edit the copied `jaci.yaml` and
scientific fragments under `stages/`:

1. Set `mesh.name`, `mesh.grid`, `mesh.graph`,
   `mesh.partitions_dir`, `mesh.nproc`, and
   `mesh.nvertlevels` to the new experiment. Choose compatible graph
   partition and input model geometry.
2. Set `static.invariant`, `static.namelist`, `static.streams`,
   `static.support_dir`, and `static.stream_lists` to reviewed
   case-specific assets; keep `geovars` and `keptvars` compatible with
   the installed MONAN-JEDI.
3. Review `stages/vbal.yaml` reduced levels, `stages/hdiag.yaml`
   diagnostics, `stages/nicas.yaml` localization/impulses and
   `stages/bflow.yaml` wind interpolation constants. These are scientific
   choices, **not** defaults that scale automatically with the mesh.
4. Use the forecast manifest generated by the corresponding MPASWF campaign
   for the desired date interval; do not reuse the original dates.
5. Use a different `project.work_root` and, if multiple science cases
   share a mesh, select a unique `project.case_id`. BFLOW now also
   includes the mesh/case identifier in its workspace name to prevent
   collisions at identical rank counts and dates.

A mesh/period change **does not** guarantee identical B products: a different
input sample set or geometry necessarily changes the calibrated covariance.
The goal is numerical reproducibility of the *original* testcase with
compatible external inputs, and scientifically valid reruns for new cases.

## Verification boundary

Automated tests verify that the testcase composes correctly, includes every
scientific fragment and preserves the original science configuration.
Full equivalence of NetCDF/SABER B products requires an HPC run with frozen
input states and a numerical regression comparison. This is not run by CI.
